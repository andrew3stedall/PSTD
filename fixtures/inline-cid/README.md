# Inline Content-ID fixture

This is a small synthetic Unicode PST used to validate attachment Content-ID
correlation. It contains three messages under `Inbox`:

- one HTML message with a uniquely matched inline PNG and a normal text file;
- one HTML message with an unmatched HTML `cid:` and an unmatched inline PNG;
- one HTML message whose `cid:` resolves to two attachments with the same
  Content-ID.

All message data is authored for this repository and uses `example.test`
addresses. It contains no private mailbox data.

## Provenance

The PST was generated from the EML files in `source/` with
[EMLtoPST](https://github.com/igrbtn/EMLtoPST) at commit
`6fe9025390a96fe0095457b56f12ce241ee4ba53`. EMLtoPST is MIT licensed. The
small `eml2pst-content-id.patch` adds the published MAPI
`PR_ATTACH_CONTENT_ID` property to the fixture generator; it is not a PSTD
runtime or build dependency.

The checked-in generated file is `inline-cid.pst` and must remain exactly
27,648 bytes with SHA-256:

`de7c775a7b92b560de5a60d79d7f3b863b764bd248cc0819e4ecf424d4063743`

The GitHub Actions fixture workflow recreates the PST from the source EML and
patch, verifies the byte hash, and then runs both PSTD and `readpst` against
it. Keeping the generator pinned and the generated bytes hashed makes any
future fixture change explicit.
